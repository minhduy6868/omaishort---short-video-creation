# 3.0 Dùng AI ở từng bước 3.1→3.5 (phương pháp)

> Đây là quy trình học của bài chương 3, không phải tính năng trong `apps/api`. README chương 3 trỏ file này. Sản phẩm không có màn "AI viết PRD".

Cách các file 3.1–3.5 được viết:

1. **Đề cương nêu mục** (khám phá, PRD, FR/NFR, user story, đặc tả).
2. **AI được phép đề xuất bố cục** theo mục đó.
3. **Repo phán quyết.** Mỗi câu phải trỏ được tới `docs/REQUIREMENTS.md`, `docs/AUTH.md`, schema, route, hoặc test. Câu không trỏ được thì chuyển vào "Báo cáo thiếu hụt", không viết thành đã có.

| Bước đề cương | File | AI đề xuất | Repo giữ |
| --- | --- | --- | --- |
| 3.1 Khám phá | [3.1-kham-pha-san-pham.md](3.1-kham-pha-san-pham.md) | persona, JTBD, đối thủ | problem lấy nguyên REQUIREMENTS §1; actor lấy AUTH; không thêm TAM/giá |
| 3.2 PRD | [3.2-prd.md](3.2-prd.md) | bố cục PRD | ghi rõ repo không có file PRD riêng; bản này là tổng hợp |
| 3.3 Phân tích | [3.3-phan-tich-yeu-cau.md](3.3-phan-tich-yeu-cau.md) | bảng FR/NFR | chỉ FR có route hoặc test |
| 3.4 User story | [3.4-user-stories-acceptance.md](3.4-user-stories-acceptance.md) | mẫu As a / Given-When-Then | đánh dấu "suy ra từ code", vì repo không có backlog story |
| 3.5 Đặc tả | [3.5-dac-ta-tinh-nang.md](3.5-dac-ta-tinh-nang.md) | một spec mỗi tính năng | Auth/Attachment bám AUTH.md; drama/news nằm rải REQUIREMENTS |

Prompt trong `prompts/` không tham gia bước này. Chúng sinh lời video (chương 2), không sinh 3.1–3.5.

Khi một kết quả AI mâu thuẫn code (ví dụ gọi news là phim nhân vật, hoặc vẽ MP4 lên Cloudflare), bản trong `docs/course/chuong-03/` giữ phía code.
