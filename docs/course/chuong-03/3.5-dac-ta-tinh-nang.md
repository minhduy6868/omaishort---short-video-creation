# 3.5 Đặc tả Tính năng (Feature Specification) — omaishort

> Nguồn: `docs/AUTH.md` (feature spec đầy đủ nhất), `docs/REQUIREMENTS.md` §5–§9, `apps/api/omaishort/main.py`, `packages/schema`.

Trong repo, **tính năng được đặc tả đầy đủ nhất** là Auth + Attachment vì đã có file hợp đồng riêng ([`docs/AUTH.md`](../../AUTH.md), 351 dòng). Các tính năng pipeline được đặc tả **rải** trong REQUIREMENTS. Phần này chuẩn hoá lại theo khung "Feature Spec" và chỉ rõ cái nào đủ / cái nào partial.

## 3.5.1 Feature: Authentication (ĐẦY ĐỦ — mẫu chuẩn)

Đây là ví dụ feature-spec hoàn chỉnh có sẵn trong repo. Tóm tắt khung (chi tiết ở AUTH §3):

- **Quyết định thiết kế + lý do bác bỏ phương án khác** (AUTH §3.1): chọn *OAuth2 password + JWT access + opaque rotating refresh trong PostgreSQL*; bác Redis session, JWT-only, API-key-as-user, hosted IdP, ChatGPT cookies.
- **Token** (§3.2): access = HS256 JWT (`sub/email/role/iat/exp/typ=access`), TTL **900s**; refresh = opaque 32-byte, lưu **SHA-256**, TTL **14 ngày**, xoay mỗi lần refresh.
- **Cookie** (§3.3): `omaishort_at`/`omaishort_rt`, httpOnly, SameSite=Lax, Secure theo `AUTH_COOKIE_SECURE` (mặc định 0 trên loopback), không set Domain.
- **Xác thực request** (§3.4): Bearer **hoặc** cookie; header thắng; thiếu/sai → 401.
- **Mật khẩu** (§3.5): scrypt (n=2¹⁴,r=8,p=1,dklen=32) + salt 16 byte, verify bằng `hmac.compare_digest`; policy 8–128 ký tự.
- **Lockout** (§3.6): theo email, 8 lần sai → 429 trong 15 phút; email lạ dùng dummy hash chống dò timing.
- **Signup** (§3.7): `AUTH_SIGNUP` mặc định 1; user đầu = operator, sau = creator.
- **Public vs protected** (§3.8): bảng phân định rõ route nào cần token.

Code hiện thực: `apps/api/omaishort/auth.py`. JWT tự ký bằng stdlib (không thư viện JWT):

```115:129:apps/api/omaishort/auth.py
def encode_access(user: dict[str, Any]) -> str:
    now = int(time.time())
    payload = {
        "sub": user["id"],
        "email": user["email"],
        "role": user["role"],
        "typ": "access",
        "iat": now,
        "exp": now + AUTH_ACCESS_TTL_SEC,
    }
    header = _b64url(json.dumps({"alg": "HS256", "typ": "JWT"}, separators=(",", ":")).encode())
    body = _b64url(json.dumps(payload, separators=(",", ":")).encode())
    sig = hmac.new(auth_secret().encode("utf-8"), f"{header}.{body}".encode("ascii"), hashlib.sha256).digest()
    return f"{header}.{body}.{_b64url(sig)}"
```

## 3.5.2 Feature: Attachments (ĐẦY ĐỦ)

AUTH §6 là spec đầy đủ: 6 kind, MIME allow, giới hạn byte, hành vi pipeline, sniff magic bytes (không tin `Content-Type`), quota, dedup theo sha256, và mục "Must not".


Bảng kind → pipeline (AUTH §6.1):

| kind | MIME | Max | Vào pipeline |
| --- | --- | --- | --- |
| face | jpeg/png/webp | 8MiB | drama refs `refs/<id>.png`, bỏ qua passport sinh |
| location | jpeg/png/webp | 8MiB | drama refs `refs/locations/<id>.png` |
| prop | jpeg/png/webp | 8MiB | drama refs `refs/props/<id>.png` |
| editorial | jpeg/png/webp | 8MiB | news/knowledge: still **đầu** waterfall |
| logo | jpeg/png/webp | 2MiB | set `mix.logo_enabled` + path |
| script | txt/md UTF-8 | 256KiB | copy provenance, **không** thay `text` |

## 3.5.3 Feature: HTTP API surface (ĐẦY ĐỦ trong code)

Toàn bộ route trong `apps/api/omaishort/main.py`, khớp AUTH §5 + REQUIREMENTS §5:

| Method + Path | Auth | Ý nghĩa |
| --- | --- | --- |
| `GET /`, `/health`, `/providers`, `/voices` | Public | trạng thái, provider, voices |
| `POST /auth/register` `/login` `/refresh` `/logout` | Public (mint session) | vòng đời phiên |
| `GET /auth/me` | Protected | thông tin user |
| `POST/GET /attachments`, `GET /attachments/{id}[/file]`, `DELETE /attachments/{id}` | Protected | quản lý attachment |
| `POST /jobs`, `GET /jobs`, `GET /jobs/{id}`, `/artifacts`, `/download` | Protected | vòng đời job |
| `GET /files/{path}` | Protected | phục vụ byte trong `data/` có kiểm sở hữu |

## 3.5.4 Feature: Pipeline & artifacts (PARTIAL — spec rải trong REQUIREMENTS)

Stage (REQUIREMENTS §5, enum `JobStage` trong models.py): `analyze → plan → refs → stills → tts → captions → render`. Knowledge topic/GitHub chèn bước `script` trước `analyze`.

Artifact trong `data/jobs/<id>/`: `script.json` (topic/GitHub), `bible.json`, `structure.json`, `storyboard.json` (viết lại sau rescale), `timeline.json` (Remotion chỉ đọc file này), `render/short.mp4`, `render/motion.json` (`kenburns|i2v|mixed`), `refs/`, `stills/`.

## 3.5.5 Feature: Beat lenses (ĐẦY ĐỦ — bảng số)

REQUIREMENTS §6 có bảng cặp shot chính xác cho drama và editorial (nguồn `_BEAT_LENSES` / `_BEAT_LENSES_EDITORIAL` trong `engine/fallback.py`). Ví dụ drama: hook = medium+zoom_in / close_up+zoom_in; ending = medium+hold / wide+zoom_out. Đây là spec "đóng" — đổi bảng phải đổi cả `fallback.py` và REQUIREMENTS trong cùng PR (§15).

## 3.5.6 Feature: Provider chains (ĐẦY ĐỦ về thứ tự)

- **Image** (REQUIREMENTS §8): Pollinations → Gemini HTTP → xAI Grok Imagine → OpenAI → placeholder.
- **Video/I2V drama** (§9): xAI Grok Imagine video → HF Spaces → WaveSpeed Wan → Pollinations Wan; một clip/scene; news/knowledge giữ Ken Burns.
- **TTS** (§9): ElevenLabs nếu có key, else edge-tts, else silence.
- **LLM**: OpenAI-compatible HTTP / ChatGPT web (knowledge VO).

Toàn bộ cấu hình bật/tắt + key nằm ở `apps/api/omaishort/config.py` (đọc từ `.env`).

## 3.5.7 Feature: Tạo job / 3 kind (ĐẦY ĐỦ — theo khung của AUTH.md)

Đây là tính năng **lõi** của sản phẩm. Phần này dựng spec theo đúng khung `docs/AUTH.md` (mục tiêu → actor → contract → luồng → data → FR → NFR → edge case → out of scope → acceptance). Nguồn: `apps/api/omaishort/main.py`, `pipeline.py`, `cli.py`, `docs/REQUIREMENTS.md` §4–§9.

### 3.5.7.1 Mục tiêu

Biến **một lần dán** (text / ý tưởng / URL bài báo / URL GitHub / chủ đề) thành **một MP4 1080×1920 @ 30fps** có VO + phụ đề karaoke, qua **một** pipeline dùng chung cho ba kind. Không thêm kind thứ tư (REQUIREMENTS §1).

### 3.5.7.2 Actors & điểm vào

| Điểm vào | Actor | Auth | Job `user_id` |
| --- | --- | --- | --- |
| `POST /jobs` (Studio) | Creator / Operator | Bắt buộc (Bearer hoặc cookie) | id của caller |
| `python -m omaishort` (CLI) | Operator | Không đăng nhập | `NULL` |

Id job: HTTP dùng `uuid4().hex[:12]`; CLI dry-run dùng tiền tố `dryrun-` + `hex[:8]` (`cli.py`).

### 3.5.7.3 Input contract

Cả hai điểm vào đều validate qua `StoryInput` — bảng luật từng field ở [3.3.3](3.3-phan-tich-yeu-cau.md). Điểm riêng của HTTP:

- `attachments[]` chỉ dùng được qua HTTP; được validate **ngay tại `POST /jobs`** bằng `uploads.load_job_files` (không tồn tại / không sở hữu / mất file trên đĩa → 404). CLI bỏ qua.
- Response: `{ "id": "<12-hex>", "status": "queued" }`; công việc chạy nền bằng `BackgroundTasks`.

### 3.5.7.4 Định tuyến theo kind (routing)

Quyết định kind xảy ra **trước** khi vào pipeline:

| Điều kiện | Kết quả | Nguồn |
| --- | --- | --- |
| `kind=brief` | → `news` | `coerce_video_kind` (models.py) |
| Story arg là URL + kind mặc định `drama` | GitHub → `knowledge`; còn lại → `news` | `cli.py` |
| URL báo VN (`vnexpress`, `tuoitre`, `thanhnien`, `dantri`, `vietnamnet`) + `language=en` | ép `language=vi` | `cli.py` |
| `kind` editorial nhưng `genre` là drama | ép `genre=news` / `knowledge` | `model_validator` (models.py) |
| `kind=knowledge` và paste là **topic** | chèn bước viết script trước analyze | `is_knowledge_topic`, `pipeline.py` |

### 3.5.7.5 Luồng xử lý (`run_job`)

```
[script?] → analyze → plan → refs → stills → tts → captions → render → done
```

Chi tiết rẽ nhánh theo kind (`apps/api/omaishort/pipeline.py`):

| Bước | Drama | News | Knowledge |
| --- | --- | --- | --- |
| script (tuỳ chọn) | — | có `source_url` → fetch bài, ghi `script.json` | topic/GitHub → fetch + `write_knowledge_script` |
| analyze | bible + 5 beat từ paste | dùng VO đã viết (`fallback_analyze`) | dùng VO đã viết |
| plan | 8–15 scene | **đúng 5** + `clamp_brief_storyboard` | **đúng 5** + clamp |
| refs | sinh passport nhân vật / location / prop | **bỏ qua** | **bỏ qua** |
| stills | ref-guided, `photo=True` | waterfall: attachment → ảnh bài → CC → sinh | như news |
| tts | VO / hội thoại | narrator | narrator |
| captions | ASS karaoke | ASS karaoke | ASS karaoke |
| render | I2V nếu có key, else Ken Burns | Ken Burns + `xfade` | Ken Burns + `xfade` |

Attachment được áp **trước** refs (`apply_attachment_files`), nên `face`/`location`/`prop` thay thế passport sinh ra, `editorial` chen đầu waterfall, `logo` set vào `mix`.

### 3.5.7.6 Artifacts & trạng thái

Ghi dần vào `data/jobs/<id>/` và cột `artifacts` (danh mục đầy đủ ở mục **3.5.4** phía trên). Trạng thái cập nhật theo từng stage qua `db.update_job(stage=…, progress=…)`; Studio **poll JSON**, không websocket (NFR8).

| Kết thúc | `status` | `stage` | `error` |
| --- | --- | --- | --- |
| Thành công | `done` | `done` | `None` |
| Thất bại | `failed` | `failed` | message + traceback (cắt 2000 ký tự cuối) |

### 3.5.7.7 Yêu cầu chức năng của riêng tính năng này

Ánh xạ sang FR gốc (REQUIREMENTS §10): FR1 (5 beat + lens), FR3 (một still/scene), FR5 (đồng hồ audio), FR6 (đúng thứ tự stage), FR7 (`StoryInput` là body), FR9 (knowledge script-first), FR10 (motion honesty), FR13 (job theo user). Acceptance chi tiết: US-B1..B10 ở [3.4](3.4-user-stories-acceptance.md).

### 3.5.7.8 Edge cases (có xử lý trong code)

| Tình huống | Hành vi |
| --- | --- |
| Không có key cloud nào | Vẫn ra MP4 (Pollinations/placeholder + edge-tts + Ken Burns) — FR8 |
| Fetch bài/topic lỗi | Bắt exception, ghi lý do vào `script.json.note`, **không** dừng job |
| TTS lỗi | Bắt exception, đi tiếp (kịch bản silence) |
| LLM trả plan sai số scene | Loại bỏ, dùng `fallback_plan` |
| LLM trả shot lung tung | `normalize_storyboard` ghi đè bằng beat lens |
| Ảnh ngang trên editorial | `conform_photo` letterbox về 9:16 |
| Attachment bị xoá sau khi job đã copy | Job giữ bản copy trong `data/jobs/<id>/` (snapshot) |
| Provider ảnh bật nhưng trả không-phải-ảnh | **Fail still**, không trộn hình que (REQUIREMENTS §8) |

### 3.5.7.9 Out of scope (của riêng tính năng này)

Không có `PUT`/`DELETE /jobs/{id}` (AUTH §4.5 nói rõ v1 không xoá job). Không có review gate `POST /jobs/{id}/approve` (P3). Không có hàng đợi Redis / nhiều worker (P6). Không có kind thứ tư.

### 3.5.7.10 Acceptance

Dry-run theo REQUIREMENTS §13 (lệnh cụ thể ở [bài thực hành](bai-thuc-hanh-3.md) Phần B), cộng test đơn vị đã liệt kê tại US-B5..B10.
